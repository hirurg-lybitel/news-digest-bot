# Как выбираются главные новости

Пайплайн отбора — **детерминированная предобработка + одна AI-оценка**. Нет ручной модерации.

## 1. Сбор (RSS)

Источники заданы в `src/sources.ts` (BBC, AP, CNN, NPR, NYT, Guardian, DW, Euronews, Al Jazeera).

Для каждого фида:
- заголовок, ссылка, краткий текст (snippet), время публикации;
- HTML в тексте убирается;
- сбой одного источника не останавливает остальные.

## 2. Фильтр свежести

Не фиксированные 24 часа — **с момента последнего успешного дайджеста**.

- Timestamp в `miniapp/data/state.json` (`lastDigestAt`)
- Первый запуск: `DEFAULT_LOOKBACK_HOURS` (по умолчанию **12**)
- Пропущенный cron: потолок `MAX_LOOKBACK_HOURS` (по умолчанию **24**)
- Расписание: **06:00 UTC** и **18:00 UTC** (09:00 и 21:00 Минск)

Новость попадает в пул, если `publishedAt >= since`. Если даты нет — оставляем.
## 3. Дедупликация

- ключ: нормализованный URL (без `#fragment`, lower case);
- один URL = одна запись;
- порядок: по дате публикации (новые выше).

## 4. Кандидаты для AI

В модель уходит **до 80** самых свежих уникальных новостей (не весь пул).

Это ограничение по токенам и шуму: AI видит актуальный срез, а не сотни однотипных заголовков.

## 5. Отбор важности (OpenAI)

Один запрос (`src/summarize.ts`) делает **и отбор, и тексты на RU+EN**.

Модель выбирает **до** `MINI_APP_TOP_N` историй (по умолчанию **30**), ранжируя по важности: **первые 10** → Telegram, **все отобранные** → Mini App (те же + дополнительные). Цель — заполнить ближе к 30, но если после дедупа получилось меньше — публикуем сколько есть, без ошибки. При сбое ответа модели — до 3 попыток; если в окне 0 кандидатов, дайджест не публикуется.

**Приоритет:**
- крупная геополитика и конфликты;
- стихийные бедствия, массовые жертвы;
- экономика с широким эффектом;
- наука / медицина (прорывы, регуляторные решения);
- landmark court / policy decisions.

**Пониженный приоритет:**
- celebrity gossip;
- мелкий спорт;
- повторяющиеся инкрементальные апдейты одной темы.

**Дедуп на уровне смысла (жёстко):** одно реальное событие (катастрофа, конфликт, решение суда и т.д.) → **одна** запись, даже если агентства дают разные форматы — breaking, explainer, science background, видео, live, «что вызвало X». Пример: паводки Непал/Тибет у DW (наука) и BBC (видео о причине) → одна история. Ссылка — самая информативная/авторитетная из каталога.

**Жёсткое правило:** `link` и `source` только из каталога — модель не может придумать URL. После ответа код отбрасывает истории с неизвестными ссылками.

## 6. Языковые версии

Для **одного и того же набора** историй генерируются:
- `title_ru`, `summary_ru`, `category_ru` — полностью на русском (заголовок переводится);
- `title_en`, `summary_en`, `category_en` — на английском.

Оба канала получают **одинаковый список событий**, различается только язык текста.

## 7. Публикация

Каждый настроенный канал (`TELEGRAM_CHANNEL_ID_RU`, `TELEGRAM_CHANNEL_ID_EN`) получает свой локализованный пост с **первыми 10** историями (или меньше, если в пуле меньше 10). В Mini App (`digest.json`) — **весь** отобранный список: те же новости, что в Telegram, плюс дополнительные до лимита `MINI_APP_TOP_N`.

---

## Что это **не** делает

- не считает «важность» по числу упоминаний в соцсетях;
- не использует ML-ранжирование кроме LLM;
- не гарантирует отсутствие ошибок перевода — нужна периодическая выборочная проверка.

## Настройка чувствительности

| Переменная | Эффект |
|------------|--------|
| `DIGEST_TOP_N` | сколько новостей в посте Telegram |
| `MINI_APP_TOP_N` | верхняя граница числа новостей в Mini App |
| `DEFAULT_LOOKBACK_HOURS` | окно при первом запуске |
| `MAX_LOOKBACK_HOURS` | потолок при пропуске cron |
| `OPENAI_MODEL` | качество отбора и формулировок |
Критерии отбора задаются в промпте `buildPrompt()` в `src/summarize.ts` — правки туда меняют «редакционную политику».
